# 帳號密碼與恢復

管理員在 `/dashboard/security` 管理帳號（從側欄底部的帳號選單或 ⌘K 進入）；一般使用者使用 `/account/security`（從「我的碼」進入）。登入畫面在寄信已配置時提供 `/reset-password` 的忘記密碼入口。這些頁面不列入搜尋索引。

## 顯示名稱

同一頁有「個人資料」區段，登入的人都能改自己的顯示名稱（管理員的名稱會顯示在控制台側欄）。表單呼叫 Better Auth 的 `POST /api/auth/update-user`，本文 `{"name": "…"}`。`src/lib/server/auth.ts` 的伺服器端鉤子會去掉前後空白、合併連續空白，只接受 1–100 個字且不含控制字元或雙向覆寫等格式字元，否則回 400 `INVALID_NAME`。初始化與註冊時輸入的名稱也套用同一規則。不支援頭像，寫入 `image` 會回 400 `IMAGE_NOT_SUPPORTED`。這裡不能改 Email。

## 首次設定與修改

- 沒有密碼的帳號（`POST /api/account/password`，本文 `{"newPassword": "…"}`）：必須已驗證信箱，且工作階段建立於最近 15 分鐘內。逾時時先重新登入；輸入兩次相同、12–128 字元的新密碼。
- 已有密碼的帳號：輸入原密碼與新密碼。成功後撤銷其他工作階段，目前工作階段由 Better Auth 更新。
- 密碼由 Better Auth 雜湊，API 不接受指定其他使用者。首次設定端點需同站 Origin、JSON 本文及本人有效 session；每帳號每分鐘最多 3 次，不能覆寫既有密碼。

Better Auth 在首次使用 Email OTP 登入尚未驗證信箱的既有帳號時，會清除原密碼連結及舊工作階段，避免信箱擁有人繼承事先建立的未知登入方式。這也適用於尚未驗證信箱的初始化管理員：首次 OTP 登入後，可在帳號安全頁重新設定密碼。不要停用這項保護、直接恢復舊密碼雜湊或在初始化時假裝信箱已驗證。

一般密碼註冊頁使用獨立的信箱驗證流程，驗證成功後保留原密碼。設定新密碼不會關閉 OTP 登入。關閉寄信功能前，先確認管理員已能使用密碼登入。

## 忘記密碼

1. 輸入帳號 Email，送出重設碼請求。無論帳號是否存在，頁面都顯示相同訊息；不存在的帳號不寄信。
2. 在同一頁輸入重設驗證碼與兩次新密碼。信件明確標示密碼重設用途；登入碼不能用來重設密碼。
3. 成功後所有既有工作階段失效，使用新密碼重新登入。驗證碼只能使用一次；錯誤、過期或重放均拒絕。

若沒有 EMAIL 綁定與 EMAIL_FROM，忘記密碼表單不提供，OTP 重設端點亦不啟用。已知原密碼的使用者仍可修改密碼；無法登入時須聯絡該部署的管理員，不開放初始化密鑰重設既有帳號的後門。

私密活動的返回目的地維持在 URL fragment，經允許路徑檢查後帶回登入頁，不送到重設 API 或郵件服務。

## 測試涵蓋範圍

自動化測試使用實際 Better Auth handler 與 SQLite，涵蓋未驗證憑證清理、首次設定、跨來源／未登入／過時 session 拒絕、競態及限流、原密碼檢查、重設用途隔離與單次使用、舊工作階段撤銷，以及寄信未配置時的行為。測試寄信使用替身，不能取代在自己的部署以真實郵件測試密碼恢復。

參考：[Better Auth Email OTP](https://www.better-auth.com/docs/plugins/email-otp)、[密碼登入與重設](https://www.better-auth.com/docs/authentication/email-password)。
