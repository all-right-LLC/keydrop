# Email 发送

Email 是可选功能；未配置时，免费领码、密码登录及一般兑换核心仍可使用。

发信使用 Cloudflare Email Sending。正式使用前，请在自己的域名实际发送验证码、码邮件与通知，确认送达情况与 SPF／DKIM／DMARC 设置。

## 邮件语言

每封邮件都使用收件人的界面语言。登录与重置密码的验证码使用发出请求的页面语言；码邮件与管理员提醒使用该账号最近使用的语言（`user.locale`）；匿名码邮件与管理员 Email 分发使用创建它们的请求语言。无法得知语言时使用英文。见[界面语言](customization.md#界面语言)。

## Cloudflare 设置

Cloudflare Email Sending Workers API 支持结构化 `send({to,from,subject,text})`，返回 messageId；服务接受邮件不等于收件人已收到。参考 [官方 Workers API](https://developers.cloudflare.com/email-service/api/send-emails/workers-api/)。

部署者完成发件域名验证后，可在 wrangler.jsonc 加入 `"send_email": [{"name":"EMAIL"}]`，在环境配置中将 EMAIL_FROM 设为已验证的发件地址，并执行 `pnpm run cf-typegen`。正式向任意收件人发信前，须确认自己的 Cloudflare 账户已开通 Email Sending 及相应的发送权限；只允许已验证目标地址的旧 Routing 配置不足以向一般客户发信。

建议使用专用的发信子域名。此设置不要求把现有收件邮箱的 MX 改为 Cloudflare；不要为了加入发信功能而破坏当前的收件设置。

## 本人发码 API

POST /api/code-email 使用登录 session 与同站 Origin，JSON 为 codeId、idempotencyKey（UUID）。每个账号每分钟最多 5 次请求。必须是本人已领取／购买的码、账号邮箱已验证，码未撤销／过期且商品未归档；不接受任意收件地址。

返回 202 与任务 id/status 表示已加入队列，不能当作已送达。相同账号与幂等键重试时返回原任务；不同码共用同一个键会被拒绝。邮件队列只保存码的标识，不保存原始码或邮箱副本；发送前重新核验所有权、有效状态与当前已验证的邮箱，再即时解密。

每五分钟的定时任务最多处理 10 封。每次发送最多等待 10 秒，失败五分钟后重试，失败五次后停止；码或资格已失效则取消。程序中断的任务在 60 秒租约过期后可被接手。发信服务商不提供端到端幂等承诺，超时或程序崩溃后重试可能重复发出同一个码，但不会重新分配库存。sent 表示服务商已接受，不代表最终投递。

“我的码”已接入发送按钮及状态显示；GET /api/code-email?id=UUID 只允许本人查询任务状态。

## 自动发码

同时设置 EMAIL、EMAIL_FROM 与 CODE_ENCRYPTION_KEY 后，每五分钟的定时任务会先从已提交的领取及已交付的订单补入最多 25 个任务，再按上述规则发送最多 10 封。有积压时会延后发出，不保证立即收到。没有配置发信服务时不会自动加入队列，不影响网站领码或付款交付。

自动发码目前支持已登录且邮箱已验证的持有人；验证邮箱后，下一次定时任务即可补入。首次启用发信服务时，也会补入仍有效的现有持有记录。匿名领取及未绑定账号的访客订单，不会把自行填写的 Email 当作已验证的收件地址。

同一账号、同一个码只会自动入队一次，共享码的不同持有人各自收到自己的邮件。定时任务重跑及程序中断不会另建任务；已取消或发送失败五次的任务也会保留去重记录，需要用户在“我的码”手动重新发送。部分／全额退款但未撤销访问权限的订单仍属于持有记录；已撤销访问权限、过期或归档的码不会新增自动任务。发送前仍会重新验证资格。

## 访客领取后绑定账号

匿名领取成功后可选择“Save to my account”（加入我的账号）。在原浏览器登录并验证邮箱后，回到领取页再次操作，即可把现有领取记录加入账号；不会重新分配码，也不会增加活动的已领取数。完成后可在“我的码”查看；未选择匿名发送的，符合上述自动发码规则；已创建匿名发送任务的，不会因绑定再自动发送一次。没有登录及验证邮箱时，原本的匿名领码仍然可用。

POST /api/claims/{claimId}/link 需要同站 Origin、登录 session、数据库中的已验证邮箱，以及领取时有效的签名浏览器 Cookie。请求不接受自行指定账号或收件邮箱；缺少或伪造 Cookie 不会创建新身份来接管旧记录。第一次绑定采用条件更新，其他账号不能覆盖；相同账号重复提交不会产生新记录。此端点不开放给 API Key／MCP 代为绑定。

绑定后会保留匿名浏览器／IP 的活动限额，账号之后的领取也计入该记录。绑定同样遵守活动的每人上限：账号已持有上限数量时，绑定返回 409 `CLAIM_LINK_LIMIT_REACHED`，该记录保持匿名，仍可在原浏览器访问；找回邮箱码时会跳过已达上限的活动。只有已绑定的账号可以恢复原结果，原浏览器退出登录或切换到另一个账号后，不能读取已绑定的记录。这不会使用户先前已复制的码失效；不要把绑定视为码的撤销或轮换。

公开活动已支持下一节的匿名发码与已验证邮箱找回。

## 匿名活动的可选 Email 副本

公开活动完成领取后，若部署已配置发信，可选择 Email a copy of this code（发送一份码到邮箱）。原码仍在页面上交付；填写 Email 并不是验证邮箱，也不能用来满足指定 Email／域名等活动资格条件。发送请求不会创建第二份领取、库存或用户账号。

`POST /api/claims/{claimId}/email` 需要同站 Origin、原始签名浏览器 Cookie、可信 IP，以及 `{"email":"recipient@example.com"}`。只允许在原匿名领取尚未绑定账号时创建新任务；不接受 userId、codeId 或任意任务标识。返回 200 与 `{job:{id,status,attempts}}` 表示该领取的发送记录，不代表送达。没有发信配置时返回 503，不新增任务。

每笔领取最多一个发送任务；收件地址转为小写并加密保存，以 HMAC 索引查重，不把未验证的 Email 写入 claims.email。相同地址重复提交沿用原任务，不同地址返回 409，发送失败后也不能更改收件人或重新分配码。提交前须确认地址正确；用户仍可保留原始码。

每个收件邮箱每小时最多 5 笔、原领取 IP 每小时最多 10 笔，数据库在插入时进行原子检查。原 IP 只保留现有的 HMAC，没有新增明文 IP。HTTP 层也沿用领码的每 IP 每分钟 30 次限流，超过返回 429；已存在的相同发送任务不占用每小时额度。

`GET /api/claims/{claimId}/email` 只允许原浏览器的持有人读取 `{job:null}` 或任务 id/status/attempts，不返回收件地址、索引或码。若领取已绑定账号，还必须登录该账号。此端点不授予其他 API Key／MCP 代理权限；所有响应均为 no-store。

每五分钟的定时任务最多处理 10 封匿名发码邮件，另有其他邮件队列。每次最多等待 10 秒，失败五分钟后重试，最多 5 次；60 秒租约到期后可被接手，第五次中断后停止。每次都会重新检查码／商品与 Stripe 来源；失效的任务会取消，但不会释放原领取。服务商接受后才记为 sent，不代表最终送达；超时可能重复发送同一个码，绝不会另配新码。

已选择发送的领取，只能绑定已验证的原收件邮箱。用户可在其他设备登录并验证该邮箱，在“我的码”点击 Find my emailed codes 找回；现有的 `POST /api/email-distributions/link` 会同时找回管理员分发与匿名领取，合计最多 100 笔。保留原匿名 subject／IP、名额及原码，不会转移已绑定的记录，也不会因找回而自动发信。失败的任务可由本人验证邮箱找回后，使用一般的本人发码功能再次发送。

本地开发使用发信替身。实际收信及邮箱验证须在部署后测试，不能把本地模拟的验证状态当作真实发信成功。

## 管理员直接通过 Email 分发

码库的“Email selected code”可将码分配给指定 Email，不要求收件人先注册，也不会替收件人创建账号。此功能与分配给现有账号是分开的；管理员须确认地址正确，邮件会包含码。收件人之后登录并验证同一个邮箱后，可在“我的码”点击 Find my emailed codes 绑定现有分发。共享激活码需先完成此绑定，才能以账号激活设备。

POST /api/email-distributions 接受 productId、codeId、email、note、idempotencyKey，仅限管理员 session 与同站 Origin。未配置 Email Sending、发件地址与加密密钥时拒绝新的分配。返回 202 与 id/status 只表示已入队。相同请求重复提交沿用原记录，收件地址加密，查重索引使用 HMAC；不同内容不能共用同一个幂等键。

GET /api/email-distributions?productId=UUID&page=1 提供每页 25 笔管理记录与 enabled。只有管理员可以解密查看收件地址，结果不含明文码。每五分钟的定时任务最多处理 10 封直接分发邮件，另有已登录用户的发码队列；每次最多等待 10 秒，五分钟后重试，五次后停止。sent 代表服务商已接受，不代表送达。

同一端点的 PATCH 接受 productId、id（分发 UUID）、idempotencyKey、note（至少 10 字）。只有 failed 且码仍有效时才允许人工重试；沿用原收件地址、原码与原分发 ID，重置本轮 attempts，但保留 total_attempts、增加 retry_count 并写入管理员审查记录。重复提交同一个重试请求不会再次重置任务。

邮件可能在超时前已经发出，因此失败或取消都不会把码释放给其他收件人；重试可能重复发出同一个码。后台分发提供失败后的人工重试与收件人绑定。

### 收件人找回与绑定

POST /api/email-distributions/link 需要登录 session 与同站 Origin，不接受收件 Email 或用户 ID。服务器从数据库取得当前已验证的邮箱，比对收件 HMAC，每次最多将 100 笔尚未绑定的记录加入该账号，返回 linked 数量。可以重复操作，不会再分配库存，也不会因绑定而重新创建自动发码任务。

绑定后“我的码”显示 Distributed by email，并沿用兑换、设备管理及本人手动发码。绑定会保留时间戳；已绑定的记录不能转移到另一个账号。原分发邮件仍发往管理员指定的原地址，不会因账号更换邮箱而改写。

## 邮件内的网站入口

发码邮件使用部署配置的 APP_URL 生成“我的码”链接，不在 URL 中放入码、Email 或登录凭证。直接 Email 分发另附使用原收件邮箱注册／登录、验证与找回记录的说明。停用 siteFeatures.myCodes 时改为首页入口，不提示使用已停用的页面。缺少或无效的网站 origin 时不插入链接；部署时仍须按初始化要求正确设置 APP_URL。

已登录账号的发码任务在第五次尝试中断后，等待租约到期即标记为失败，不再由后续定时任务接手。这项上限也适用于管理员直接分发的发信任务。

## 管理员事件提醒

`/dashboard/notifications` 是管理员通知中心，每页 25 笔，可切换待处理与已解决。明确拒绝、发放结果不明及外部撤销会分别说明，未知发放结果链接到人工核对页。明确拒绝不再导向仅列出结果不明操作的页面；用户重试成功或管理员完成核对后，原通知会被解决。

`siteFeatures.adminNotificationEmail` 默认开启。配置 EMAIL、EMAIL_FROM、有效的 APP_URL，且安装记录中的管理员邮箱已验证后，定时任务每轮补入最多 25 个仍未解决的通知版本、发送最多 10 封。发送前会重新读取当前管理员与邮箱验证状态；不采用任意配置的地址。停用此功能或未配置发信时，后台通知仍会保留。

每个通知的 occurrence 独立去重；同一版本不会重建，新的失败次数可以产生新的提醒。若发送前通知已解决、被新版本取代或管理员失去验证，旧任务会取消。已取消／失败的同一版本不会自动重建，管理员仍应以后台为准。

邮件只带事件类别、操作 ID 与登录后的通知中心链接，不含码、商品名称、客户邮箱或外部错误正文。每次发送最多等待 10 秒，失败间隔至少五分钟，最多五次；60 秒租约过期后可被接手，第五次租约过期后直接停止。服务商接受后记为 sent，不代表送达；超时或程序中断仍可能造成重复邮件，无法宣称端到端恰好一次。

去重、重试上限、取消及租约保护已有自动化测试；实际发送请在自己的环境中验证。
