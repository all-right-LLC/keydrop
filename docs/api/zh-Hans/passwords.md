# 账号密码与恢复

管理员在 `/dashboard/security` 管理账号（从侧栏底部的账号菜单或 ⌘K 进入）；普通用户使用 `/account/security`（从“我的码”进入）。登录界面在已配置发信时提供 `/reset-password` 的忘记密码入口。这些页面不会被搜索引擎收录。

## 显示名称

同一页有“个人资料”区块，已登录的人都能修改自己的显示名称（管理员的名称会显示在控制台侧栏）。表单调用 Better Auth 的 `POST /api/auth/update-user`，正文 `{"name": "…"}`。`src/lib/server/auth.ts` 中的服务器端钩子会去掉首尾空白、合并连续空白，只接受 1–100 个字且不含控制字符或双向覆盖等格式字符，否则返回 400 `INVALID_NAME`。初始化与注册时输入的名称也适用同一规则。不支持头像，写入 `image` 会返回 400 `IMAGE_NOT_SUPPORTED`。这里不能修改 Email。

## 首次设置与修改

- 没有密码的账号（`POST /api/account/password`，正文 `{"newPassword": "…"}`）：必须已验证邮箱，且会话创建于最近 15 分钟内。超时则先重新登录；输入两次相同的、12–128 个字符的新密码。
- 已有密码的账号：输入原密码与新密码。成功后撤销其他会话，当前会话由 Better Auth 更新。
- 密码由 Better Auth 进行哈希处理，API 不接受指定其他用户。首次设置端点需要同站 Origin、JSON 正文及本人有效的 session；每个账号每分钟最多 3 次，不能覆盖已有密码。

Better Auth 在首次使用 Email OTP 登录尚未验证邮箱的已有账号时，会清除原有的密码关联及旧会话，避免邮箱所有者继承事先创建的未知登录方式。这也适用于尚未验证邮箱的初始化管理员：首次 OTP 登录后，可在账号安全页重新设置密码。不要停用这项保护、直接恢复旧的密码哈希，或在初始化时假装邮箱已验证。

普通的密码注册页使用独立的邮箱验证流程，验证成功后保留原密码。设置新密码不会关闭 OTP 登录。关闭发信功能前，请先确认管理员已能使用密码登录。

## 忘记密码

1. 输入账号 Email，提交重置码请求。无论账号是否存在，页面都显示相同的信息；不存在的账号不会收到邮件。
2. 在同一页输入重置验证码与两次新密码。邮件会明确标示用于密码重置；登录码不能用来重置密码。
3. 成功后所有已有会话失效，请使用新密码重新登录。验证码只能使用一次；错误、过期或重放均会被拒绝。

若没有 EMAIL 绑定与 EMAIL_FROM，则不提供忘记密码表单，OTP 重置端点也不会启用。已知原密码的用户仍可修改密码；无法登录时须联系该部署的管理员，不开放用初始化密钥重置已有账号的后门。

私密活动的返回目标保留在 URL fragment 中，经过允许路径检查后带回登录页，不会发送到重置 API 或邮件服务。

## 测试覆盖

本地测试使用实际的 Better Auth handler 与 SQLite，涵盖未验证凭证清理、首次设置、跨来源／未登录／过时 session 的拒绝、竞态及限流、原密码检查、重置用途隔离与单次使用、旧会话撤销，以及未配置发信时的行为。测试发信使用替身，不能取代在你自己的部署中实际检查邮件找回。
